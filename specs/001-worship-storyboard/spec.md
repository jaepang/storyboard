## User Scenarios & Testing *(mandatory)*

### User Story 1 - 콘티 기본 생성 및 곡 관리 (Priority: P1)

찬양 인도자가 주간 예배를 위한 콘티를 생성하고, 곡 목록을 관리할 수 있다. 콘티 제목과 날짜를 입력하고, 곡을 추가/삭제/순서 변경할 수 있으며, 각 곡의 기본 정보(제목, BPM, 송폼)를 입력할 수 있다.

**Why this priority**: 콘티 생성과 곡 관리는 시스템의 핵심 기능으로, 이것 없이는 다른 기능을 사용할 수 없다. 가장 기본적인 워크플로우를 완성하는 MVP 기능이다.

**Independent Test**: 콘티를 생성하고 곡 목록을 편집한 후 저장하여, 반주자가 해당 콘티를 조회할 수 있으면 독립적으로 테스트 완료된다.

**Acceptance Scenarios**:

1. **Given** 인도자가 시스템에 접속했을 때, **When** "콘티 생성" 버튼을 클릭하고 제목과 날짜를 입력하면, **Then** 빈 곡 목록을 가진 새 콘티가 생성된다
2. **Given** 콘티가 생성되었을 때, **When** "곡 추가" 버튼을 클릭하고 곡 제목을 입력하면, **Then** 곡이 목록에 추가된다
3. **Given** 곡 목록에 여러 곡이 있을 때, **When** 드래그 앤 드롭으로 곡 순서를 변경하면, **Then** 변경된 순서가 즉시 반영된다
4. **Given** 곡이 선택되었을 때, **When** BPM과 송폼을 입력하면, **Then** 해당 곡의 정보가 저장된다
5. **Given** 콘티 편집이 완료되었을 때, **When** "저장" 버튼을 클릭하면, **Then** 콘티가 저장되고 반주자가 조회할 수 있게 된다
6. **Given** 콘티를 편집하는 동안 다른 사용자가 동일한 콘티를 수정하여 저장했을 때, **When** 현재 사용자가 저장을 시도하면, **Then** 충돌 경고가 표시되고 덮어쓰기 또는 취소를 선택할 수 있다
7. **Given** 기존 곡을 다른 콘티에 추가할 때, **When** 곡을 선택하여 추가하면, **Then** 해당 곡의 악보와 주석이 독립적으로 복사되어 새 콘티에서 수정해도 원본에 영향을 주지 않는다

### User Story 2 - 악보 파일 업로드 및 페이지 편집 (Priority: P2)

찬양 인도자가 각 곡에 악보 파일(PDF 또는 이미지)을 업로드하고, 각 페이지의 크기, 위치, 자르기 영역을 조정할 수 있다. 또한 송폼과 BPM 텍스트의 폰트 크기를 페이지별로 조정할 수 있다.

**Why this priority**: 악보는 반주자에게 필수적인 정보이지만, P1의 기본 콘티 생성 기능이 먼저 완성되어야 악보를 추가할 수 있다. 악보 편집 기능은 콘티의 완성도를 높이는 중요한 기능이다.

**Independent Test**: 곡에 악보를 업로드하고 페이지 편집을 수행한 후, PDF 미리보기에서 편집이 올바르게 반영되는지 확인하면 독립적으로 테스트 완료된다.

**Acceptance Scenarios**:

1. **Given** 곡이 선택되었을 때, **When** PDF 또는 이미지 파일을 업로드하면, **Then** 악보 파일이 저장되고 페이지 목록이 표시된다
2. **Given** 악보 페이지가 표시되었을 때, **When** 확대/축소 슬라이더를 조정하면, **Then** 페이지 크기가 변경되고 메타데이터에 저장된다
3. **Given** 악보 페이지가 표시되었을 때, **When** 드래그로 위치를 조정하면, **Then** 페이지 위치가 변경되고 메타데이터에 저장된다
4. **Given** 악보 페이지가 표시되었을 때, **When** 자르기 도구로 영역을 선택하면, **Then** 선택된 영역만 표시되고 자르기 정보가 메타데이터에 저장된다
5. **Given** 악보 페이지가 표시되었을 때, **When** 송폼/BPM 폰트 크기를 조정하면, **Then** 텍스트 크기가 변경되고 메타데이터에 저장된다

---

### User Story 3 - 악보 주석 작성 (Priority: P3)

찬양 인도자가 악보 페이지에 벡터 기반의 펜 드로잉으로 주석을 작성할 수 있다. 색상과 두께를 선택하여 자유롭게 그릴 수 있으며, 작성한 주석은 저장되어 PDF에 포함된다.

**Why this priority**: 주석 기능은 악보에 추가적인 정보를 제공하는 유용한 기능이지만, 필수는 아니다. P1과 P2의 핵심 기능이 완성된 후 추가하면 콘티의 유용성을 더욱 높일 수 있다.

**Independent Test**: 악보 페이지에 주석을 작성하고 저장한 후, PDF 다운로드 시 주석이 포함되어 있는지 확인하면 독립적으로 테스트 완료된다.

**Acceptance Scenarios**:

1. **Given** 악보 페이지 편집 모드일 때, **When** 펜 도구를 선택하고 색상과 두께를 설정하면, **Then** 선택한 설정이 활성화된다
2. **Given** 펜 도구가 활성화되었을 때, **When** 화면에 드로잉을 하면, **Then** 벡터 경로가 생성되고 화면에 표시된다
3. **Given** 주석이 작성되었을 때, **When** "저장" 버튼을 클릭하면, **Then** 주석 데이터가 JSON 형태로 저장된다
4. **Given** 주석이 저장되었을 때, **When** 페이지를 다시 로드하면, **Then** 저장된 주석이 화면에 표시된다

### User Story 4 - 유튜브 재생목록 연동 (Priority: P4)

찬양 인도자가 유튜브 재생목록 URL을 입력하면, 재생목록의 영상 개수를 기반으로 초기 곡 목록이 자동 생성된다.

**Why this priority**: 유튜브 연동은 편의 기능으로, 수동으로 곡을 추가하는 것도 가능하므로 우선순위가 낮다. 핵심 기능이 모두 완성된 후 추가하면 사용자 경험을 향상시킬 수 있다.

**Independent Test**: 유튜브 재생목록 URL을 입력하고 초기 곡 목록이 생성되는지 확인하면 독립적으로 테스트 완료된다.

**Acceptance Scenarios**:

1. **Given** 콘티 생성 화면일 때, **When** 유튜브 재생목록 URL을 입력하면, **Then** 재생목록의 영상 개수가 추출된다
2. **Given** 영상 개수가 추출되었을 때, **When** "곡 목록 생성" 버튼을 클릭하면, **Then** 영상 개수만큼 빈 곡이 생성된다
3. **Given** 곡 목록이 자동 생성되었을 때, **When** 각 곡의 정보를 수동으로 입력하면, **Then** 일반 곡 편집 흐름과 동일하게 작동한다

---

### User Story 5 - 콘티 조회 및 검색 (Priority: P1)

반주자가 콘티 목록을 조회하고, 콘티명이나 곡명으로 검색할 수 있으며, 날짜 범위로 필터링할 수 있다.

**Why this priority**: 반주자가 필요한 콘티를 찾는 것은 핵심 기능이다. 인도자가 콘티를 생성하는 것만큼 중요하므로 P1으로 분류한다.

**Independent Test**: 콘티 목록을 조회하고 검색 필터를 적용하여 원하는 콘티를 찾을 수 있으면 독립적으로 테스트 완료된다.

**Acceptance Scenarios**:

1. **Given** 반주자가 시스템에 접속했을 때, **When** 콘티 목록 페이지를 열면, **Then** 모든 콘티가 최신순으로 표시된다
2. **Given** 콘티 목록이 표시되었을 때, **When** 검색창에 콘티명을 입력하면, **Then** 해당 텍스트를 포함하는 콘티만 표시된다
3. **Given** 콘티 목록이 표시되었을 때, **When** 검색창에 곡명을 입력하면, **Then** 해당 곡을 포함하는 콘티만 표시된다
4. **Given** 콘티 목록이 표시되었을 때, **When** 날짜 범위를 선택하면, **Then** 해당 기간의 콘티만 표시된다

---

### User Story 6 - 콘티 미리보기 및 PDF 다운로드 (Priority: P1)

반주자가 콘티의 미리보기를 확인하거나, PDF 형태로 다운로드할 수 있다. PDF에는 곡 번호, 송폼, BPM, 악보, 주석이 모두 포함되며, 페이지 편집 메타데이터가 반영된다.

**Why this priority**: 콘티를 PDF로 다운로드하는 것은 반주자의 핵심 사용 사례이다. 인도자가 작성한 콘티를 실제로 활용하는 단계이므로 P1으로 분류한다.

**Independent Test**: 콘티를 선택하고 PDF를 다운로드하여, 모든 정보가 올바르게 포함되어 있는지 확인하면 독립적으로 테스트 완료된다.

**Acceptance Scenarios**:

1. **Given** 콘티 목록에서 콘티를 선택했을 때, **When** "미리보기" 버튼을 클릭하면, **Then** 콘티의 전체 내용이 화면에 표시된다
2. **Given** 콘티 목록에서 콘티를 선택했을 때, **When** "PDF 다운로드" 버튼을 클릭하면, **Then** 1-4초 내에 PDF 파일이 생성되어 다운로드된다
3. **Given** PDF가 생성되었을 때, **When** PDF를 열어보면, **Then** 각 곡 페이지마다 곡 번호, 송폼(빨간색), BPM(첫 페이지만, 주황색), 악보, 주석이 포함되어 있다
4. **Given** 페이지 편집 메타데이터가 있을 때, **When** PDF를 생성하면, **Then** scale, position, crop 설정이 반영된 악보가 표시된다
5. **Given** 폰트 크기 메타데이터가 있을 때, **When** PDF를 생성하면, **Then** 설정된 폰트 크기로 송폼과 BPM이 표시된다
6. **Given** BPM 배열에 여러 값이 있을 때, **When** PDF를 생성하면, **Then** 첫 페이지에 "120 → 140 → 100" 형태로 화살표로 연결되어 표시된다

---

### Edge Cases

- **PDF 페이지가 많은 경우**: 악보가 10페이지 이상인 경우에도 PDF 렌더링이 4초 이내에 완료되어야 함
- **송폼이 매우 긴 경우**: 송폼 배열에 20개 이상의 항목이 있을 때 UI가 스크롤 가능하거나 페이지 분할되어야 함
- **파일 업로드 실패**: 네트워크 오류나 저장소 문제로 파일 업로드가 실패할 경우 명확한 에러 메시지 표시
- **동일한 곡 재사용**: 여러 콘티에서 동일한 곡을 재사용할 때 악보와 주석이 콘티에 추가되는 시점에 독립적으로 복사되어, 각 콘티에서 수정해도 다른 콘티에 영향을 주지 않음
- **주석 페이지 범위**: 주석이 악보의 여러 페이지에 걸쳐 있을 때 페이지별로 분리되어 저장되는지 확인 필요
- **빈 콘티 다운로드**: 곡이 하나도 없는 콘티를 PDF로 다운로드할 때 적절한 안내 메시지 표시
- **BPM 배열 처리**: BPM이 여러 개인 경우(예: [120, 140, 100]) 첫 페이지에 "120 → 140 → 100" 형태로 화살표로 연결하여 템포 변경을 명확히 표시
- **동시 편집 충돌**: 여러 사용자가 동일한 콘티를 동시에 편집할 때 낙관적 잠금 방식으로 충돌을 감지하고, 충돌 발생 시 사용자에게 경고 메시지와 함께 덮어쓰기 또는 취소 옵션 제공

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 콘티 생성 시 제목, 날짜, 곡 목록을 저장할 수 있어야 한다
- **FR-002**: 시스템은 곡을 독립적으로 저장하여 여러 콘티에서 재사용할 수 있어야 한다
- **FR-003**: 시스템은 곡에 제목, BPM 배열, 송폼 배열을 저장할 수 있어야 한다
- **FR-004**: 시스템은 송폼을 `{ name: string, form?: string }` 형태로 저장하고, 출력 시 "name (form)" 또는 "name" 형태로 표시해야 한다
- **FR-005**: 시스템은 송폼 템플릿(intro, inter, outro, V, C, V1-V4, C1-C4, B, T)을 제공하고, 자유 입력도 허용해야 한다
- **FR-006**: 시스템은 PDF 또는 이미지 형태의 악보 파일을 업로드하고 저장할 수 있어야 한다
- **FR-007**: 시스템은 악보 파일을 오브젝트 스토리지(S3 등)에 저장해야 한다
- **FR-008**: 시스템은 페이지별 편집 메타데이터(scale, position, crop, songFormFontSize, bpmFontSize)를 JSON 형태로 저장해야 한다
- **FR-009**: 시스템은 벡터 기반 주석(색상, 두께, 좌표 배열)을 JSON 형태로 저장해야 한다
- **FR-010**: 시스템은 콘티명으로 LIKE 검색을 지원해야 한다
- **FR-011**: 시스템은 곡명으로 LIKE 검색을 지원해야 한다 (콘티에 포함된 곡 기준)
- **FR-012**: 시스템은 날짜 범위로 콘티를 필터링할 수 있어야 한다
- **FR-013**: 시스템은 콘티 미리보기 기능을 제공해야 한다
- **FR-014**: 시스템은 콘티를 PDF 형태로 다운로드할 수 있어야 한다
- **FR-015**: PDF 렌더링 시 각 페이지에 곡 번호, 송폼(빨간색), BPM(첫 페이지만, 주황색), 악보, 주석을 포함해야 한다
- **FR-016**: PDF 렌더링 시 페이지 편집 메타데이터를 반영해야 한다
- **FR-017**: PDF 다운로드는 실시간 렌더링으로 처리되며, 1-4초 내에 완료되어야 한다
- **FR-018**: 시스템은 유튜브 재생목록 URL을 입력받아 영상 개수를 추출할 수 있어야 한다
- **FR-019**: 시스템은 유튜브 영상 개수를 기반으로 초기 곡 목록을 생성할 수 있어야 한다
- **FR-020**: 시스템은 콘티와 곡의 생성/수정 시간을 자동으로 기록해야 한다
- **FR-021**: 시스템은 낙관적 잠금을 사용하여 동시 편집 충돌을 감지하고, 충돌 발생 시 사용자에게 경고 메시지를 표시하며 덮어쓰기 또는 취소 옵션을 제공해야 한다
- **FR-022**: 시스템은 기존 곡을 콘티에 추가할 때 악보 파일, 페이지 편집 메타데이터, 주석을 독립적으로 복사하여 저장해야 한다
- **FR-023**: 시스템은 복사된 악보/주석이 원본 곡에 영향을 주지 않도록 각 콘티-곡 조합마다 독립적인 데이터를 유지해야 한다
- **FR-024**: 시스템은 BPM 배열에 여러 값이 있을 경우 첫 페이지에 "BPM1 → BPM2 → BPM3" 형태로 화살표로 연결하여 표시해야 한다

### Key Entities

- **Conti (콘티)**: 주간 예배 찬양 순서를 나타내며, 제목, 날짜, 곡 목록, 생성/수정 시간, 버전 정보를 포함한다. 여러 곡을 특정 순서로 참조한다.
- **Song (곡)**: 개별 찬양곡의 기본 정보를 나타내며, 제목, 생성/수정 시간을 포함한다. 여러 콘티에서 재사용될 수 있다.
- **ContiSong (콘티-곡 인스턴스)**: 특정 콘티 내 특정 곡의 인스턴스를 나타내며, 콘티 ID, 곡 ID, 순서, BPM 배열, 송폼 배열, 악보 파일, 페이지 편집 메타데이터, 주석을 포함한다. 곡이 콘티에 추가될 때 생성되며, 독립적으로 편집 가능하다.
- **SongForm (송폼)**: 곡의 구조를 나타내는 단위로, name(예: intro, V1, C)과 선택적 form(예: 반복, 변형) 정보를 포함한다. ContiSong에 속하며, 순서가 중요하고 중복 가능하다.
- **ScoreFile (악보 파일)**: PDF 또는 이미지 형태의 악보 파일로, 파일 URL과 파일 타입을 포함한다. ContiSong에 속한다.
- **PageEditMetadata (페이지 편집 메타데이터)**: 악보 페이지별 편집 정보로, 페이지 인덱스, 확대/축소 비율, 위치, 자르기 영역, 송폼/BPM 폰트 크기를 포함한다. ContiSong에 속한다.
- **Annotation (주석)**: 악보 페이지에 작성된 벡터 기반 드로잉으로, 페이지 인덱스, 스트로크 배열(ID, 색상, 두께, 좌표 배열)을 포함한다. ContiSong에 속한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 인도자는 콘티를 생성하고 10개의 곡을 추가하는 작업을 10분 이내에 완료할 수 있다
- **SC-002**: 악보 파일 업로드 후 페이지 편집 작업을 곡당 평균 2분 이내에 완료할 수 있다
- **SC-003**: 반주자는 콘티 목록에서 원하는 콘티를 검색하여 30초 이내에 찾을 수 있다
- **SC-004**: 콘티 PDF 다운로드가 모든 경우에 4초 이내에 완료된다
- **SC-005**: 시스템은 10개 이상의 페이지를 가진 악보도 지연 없이 처리할 수 있다
- **SC-006**: 주석 작성 시 드로잉 경로가 실시간으로 렌더링되어 사용자 입력에 즉시 반응한다
- **SC-007**: 유튜브 재생목록 연동 시 5초 이내에 영상 개수를 추출하고 곡 목록을 생성한다
- **SC-008**: 반주자의 90% 이상이 첫 사용 시 별도의 안내 없이 콘티를 검색하고 다운로드할 수 있다
- **SC-009**: 곡을 여러 콘티에 추가해도 각 콘티의 악보/주석 수정이 다른 콘티에 영향을 주지 않는다
- **SC-010**: 동시 편집 충돌 발생 시 사용자가 1분 이내에 충돌을 인지하고 해결할 수 있다

## Assumptions

- 사용자는 웹 브라우저를 통해 시스템에 접근한다
- 악보 파일은 일반적으로 1-10페이지 정도이며, 최대 20페이지를 지원한다
- BPM 배열은 일반적으로 1-3개의 값을 가지며, 템포 변경을 나타낸다
- 송폼 배열은 일반적으로 5-15개의 항목을 가진다
- 주석은 페이지별로 독립적으로 관리된다
- 유튜브 API는 재생목록의 영상 개수를 추출하는 데 사용되며, 영상 제목은 자동으로 가져오지 않는다
- 업로더(인도자)와 다운로더(반주자)는 동일한 권한을 가지며, 별도의 인증/인가 구분은 없다
- PDF 렌더링은 서버 사이드에서 처리된다
- 오브젝트 스토리지는 AWS S3 또는 호환 스토리지를 사용한다
- 동시에 동일한 콘티를 편집하는 사용자는 2-3명 이하로 제한적이다
- 곡의 악보 파일은 재사용 시 오브젝트 스토리지에 복사되지 않고 동일한 파일을 참조하여 저장 공간을 절약한다
